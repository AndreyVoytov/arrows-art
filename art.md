# Алгоритм генерации декора

Этот процесс нужен для вариаций декора, которые выглядят как новые предметы, но остаются совместимыми с текущей комнатой: тот же ракурс, тот же размер спрайта, прозрачный фон, без ощущения "перекрашенной копии".

## 1. Брать оригинал как технический референс

- Сначала открыть оригинальный ассет из `images/rooms/<roomId>/`.
- Зафиксировать canvas: ширина, высота и занимаемая область по alpha.
- Зафиксировать сторону перспективы:
  - предметы на левой стене room1 (`door`, `cupboard`) должны смотреть как объекты с `angle: 135`;
  - предметы на правой стене (`window`, `picture`) должны смотреть как объекты с `angle: 225`;
  - напольные предметы сверяются по направлению ковра/скамьи в комнате.
- Для дверей отдельно проверять сторону ручки. Если флип переносит ручку на неверную сторону, такой флип не использовать.

## 2. Генерировать по одному предмету

Лучший результат получается не батчем и не вырезанием из общей сцены, а отдельной генерацией каждого объекта.

В промпте обязательно указывать:

- `single isolated game asset`;
- стиль: polished Playrix-like hidden object / room renovation asset;
- тот же тип объекта, но не копия оригинала;
- точный ракурс: `same isometric room perspective`, `same facing direction as the reference`;
- габариты: `fit the same silhouette and proportions`;
- прозрачность через chroma-key: `perfectly flat solid #00ff00 background`, `no shadow`, `no floor plane`;
- запреты: `no text`, `no watermark`, `do not use #00ff00 in the subject`.

Хороший творческий прием: задавать не "вариант того же шкафа", а новый объект с тем же игровым названием. Например:

- шкаф B: светлый скандинавский шкаф с ротангом, открытой боковой секцией и пастельными ящиками;
- шкаф C: строгий немецкий шкаф с фрезерованными фасадами и приглушенными зелено-голубыми акцентами;
- ковёр B: пастельный розовый, оранжевый, зеленый, голубой;
- ковёр C: спокойный геометрический бежевый с небольшими цветными акцентами.

## 3. Убирать фон локально

После генерации:

1. Взять PNG из `C:/Users/voito/.codex/generated_images/...`.
2. Удалить только chroma-key зеленый, не вырезая настоящую зелень растений.
3. Использовать строгий порог для фона: яркий зеленый с большим отрывом от красного/синего.
4. На краях делать легкий despill и мягкую alpha-обработку, чтобы не оставался зеленый контур.

Важно: для растений нельзя агрессивно удалять все зеленые пиксели, иначе листья станут дырявыми.

## 4. Вписывать в исходный canvas

Финальный PNG должен сохранять контракт оригинального ассета:

- тот же размер файла-спрайта;
- та же alpha-занятость, если объект должен занимать тот же объем в комнате;
- тот же `imageId`, если конфиг уже на него ссылается;
- прозрачные углы;
- без цветного фона и без теней вне объекта.

Для room1 использовался строгий fit в canvas оригинала, чтобы варианты A/B/C не меняли масштаб в комнате.

## 5. Проверять ориентацию в комнате

Изолированный контакт-лист недостаточен. Нужно собрать композит поверх `room_bg.png`:

- variant A рядом с B/C;
- все предметы на их реальных `x`, `y`, `width`, `height`;
- сравнить боковые плоскости шкафов, дверей, окон и картин;
- если объект зеркален, флипнуть только этот PNG и снова проверить в комнате.

Для текущих ассетов room1 после проверки был флипнут только `cupboard_C.png`: у него боковая грань была на противоположной стороне. Двери не флипались, потому что ручки при флипе уходят на неверную сторону. `window` и `picture` остались в текущем направлении, так как лучше совпадают с правой стеной.

## 6. Финальная проверка

После замены PNG:

```bash
cmd /c npm run atlases
cmd /c npm run build
```

Минимальные проверки:

- JSON комнаты валиден;
- все `imageId` из `config/room*.json` существуют;
- новые PNG имеют правильный размер;
- alpha не пустая;
- нет остатков chroma-key зеленого;
- нужные frames есть в `images/atlases/rooms_<roomId>.json`.
